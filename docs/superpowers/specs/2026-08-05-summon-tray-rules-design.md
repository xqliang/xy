# 征兵候选区规则与交换修复

日期：2026-08-05  
状态：已定稿（待实现）  
范围：`web` 局内征兵（`Battle.summon`）、候选区 UI、候选区→棋盘拖拽交换

## 背景

局内「征兵」把随机候选（兵种 / 铲子）放入底部候选区，再由玩家拖到棋盘布阵。当前体验问题：

1. 再次征兵时，上次未上阵的候选仍会留下（与「覆盖本轮」预期不符）。
2. 开局首次征兵需要保证足够的兵种数量。
3. 单次征兵内同一道具可刷过多。
4. 从候选区拖到已有单位的格子时，交换不可靠（玩家实测失败）。

本设计只改征兵产出与落点交换，不引入武将信物等未实现系统。

## 目标行为

### 1. 再征兵清空残留

- 点击「征兵」且蟠桃足够时：**不因候选区非空而拦截**。
- 扣费成功后、写入新候选前：将 `tray` **强制置空**。
- 上次未上阵的兵种 / 铲子全部丢弃，不得与本轮新手牌叠加或残留。

### 2. 每轮产量

- 每轮固定产出 **5** 个候选（`summonDraws = 5`，`traySize = 5`）。

### 3. 首次征兵最少兵种

- 本局第一次成功征兵：5 个槽位中 **兵种数量 ≥ 4**（允许至多 1 个铲子）。
- 「首次」以本局成功征兵次数计（`summonCount === 0` 时为本轮首次）。

### 4. 同键上限

- 每一轮征兵内，同一 token 键最多出现 **3** 次。
- 键定义：
  - 兵种：`unit:<type>`（如棍猴 / 枪天兵 / 天马骑兵 / 神箭手）
  - 铲子：`shovel`
- 实现方式：**约束抽取**——每抽一格时，只从「当前计数 &lt; 3」的合法键中选取。
- 非首次征兵仍可按 `shovelDrawChance` 尝试出铲子，但若铲子已达上限则改抽兵种。

### 5. 候选区 → 棋盘交换

从候选区拖 **兵种** 落到已解锁格时：

| 目标格状态 | 结果 |
|-----------|------|
| 空 | 放置，令牌移出候选区 |
| 已有单位且同型同级可合并 | 合并升阶，令牌移出候选区 |
| 已有单位且不可合并 | **交换**：新兵入格，原单位回到该候选槽（不删除） |
| 未解锁 | 失败并提示 |

铲子仍只能挖**锁定**的可摆放绿格；落到单位格不交换。

拖拽链路（`pointerup` → 落点命中 → `placeFromTray`）必须保证落到单位格时稳定触发合并/交换；并加回归用例锁住异型格交换。

## 非目标

- 不改变征兵蟠桃成本曲线（`summonCostStart` / `summonCostStep` / 仙缘幡修正）。
- 不实现设计文档中的武将信物 / 定海符扩展池。
- 不改变棋盘→棋盘的 `dragUnit` 移动/合并/交换语义（除非与本次拖拽命中修复共用代码）。

## 实现要点

### 数据与逻辑（`web/src/battle.ts`）

- 增加 `summonCount`（或等价），每次成功征兵 +1。
- `summon()` 流程：
  1. 校验状态与蟠桃；
  2. 扣费、递增成本、闪光；
  3. `tray = []`；
  4. 按约束抽取填满 5 格（首次保证兵种 ≥ 4）；
  5. `summonCount++`；提示文案可保持「拖到绿格…」。
- 抽取辅助：维护 `Map`/`Record` 计数；选键时过滤已满 3 的键；首次在已抽铲子达 1 个后禁止再抽铲子，并在填满前保证兵种数达标（若随机结果将导致兵种 &lt; 4，则后续槽位强制兵种）。

### UI（`web/src/render.ts`）

- 候选区继续 5 槽布局（若布局常量写死 5，核对与 `traySize` 一致即可）。
- 「征兵」按钮在桃足够时可用，**不**因 `tray.length > 0` 禁用。

### 交互（`web/src/main.ts`）

- 排查并修复候选区拖放到棋盘单位格时交换失败的原因（例如落点被候选区命中抢先、`pointerup` 坐标、目标格解析等）。
- 修复后：异型单位格交换、同型同级合并均可通过指针操作完成。

### 测试

至少覆盖：

1. 征兵前 tray 有残留 → 征兵后仅本轮 5 个，无历史 token。
2. 首次征兵 → 兵种数 ≥ 4，总数 5。
3. 任意一轮 → 任一键出现次数 ≤ 3。
4. `placeFromTray`：异型已占格 → tray 与棋盘互换；同型同级 → 合并。

## 验收清单

- [ ] 候选有残留时再征兵 → 只剩本轮 5 个
- [ ] 开局首次征兵 → 5 槽且兵种 ≥ 4
- [ ] 任意一轮 → 同 type / 铲子 ≤ 3
- [ ] 候选兵拖到异型已占格 → 交换成功
- [ ] 候选兵拖到同型同级格 → 合并成功

## 风险与说明

- 源码中已有 `this.tray = []`，但玩家实测仍见残留；实现时必须以行为与回归测试为准，排查是否存在未走 `summon()` 的路径、UI 未刷新、或命中/按钮逻辑导致「看起来像没清空」。
- 约束抽取在铲子概率与上限同时存在时，实际铲子出现率会略低于裸概率，可接受。
