# 低端机战斗帧率自适应设计:画质档位加深 + 基础渲染降载

> 状态:需求已与用户确认(2026-09-01):目标「低端机战斗稳 30~40fps,折中,保核心战斗清晰度、特效可明显减弱」;深度「特效 + 基础渲染降载(渐变缓存化/全屏填充降频/关 blur·毛玻璃/爆点减量),不降整体分辨率」;开关「纯自动,不暴露手动画质档」。用户在 worktree 开发、最终验收。

## 目标

在低端机上把**战斗屏**稳定在 30~40fps:以一套**纯自动的画质档位机制**为中心——开机按设备性能分级定初始档、战斗中按平滑帧时(EMA)动态升降档,档位同时驱动**特效粒子降密度**与**基础渲染降载**(径向渐变缓存化/复用、全屏填充降频、关 blur 与毛玻璃、命中爆点减量)。不降整体渲染分辨率,不暴露手动画质设置。

## 背景与动机

- 项目**已有一套很浅的自适应特效档位**:`main.ts:215-217` 的 `frameMsEma`/`fxQualityLevel`,`main.ts:2954-2958` 的战斗屏 EMA 帧时监视(>26ms 降档、<19ms 恢复,迟滞防抖),`render.ts:2739-2748` 的 `setFxQuality`/`getFxQuality`(clamp 0.3~1)。但它只有**满档 1 / 省档 0.4 两档**,且只作用 **3 个特效点**(`render.ts:2791` 灼烧火舌数、`:2804` 上升火星、`:2850` 冰晶数)。
- 它**不触及真正的大头**:每帧径向渐变(旧诊断 28.5 个/帧,`drawUnlockedCellFace` 等)、全屏填充(背景 cover + 半透明 fillRect,2-3 次/帧)、`drawImage` 数量、命中爆点粒子。低端机上这些比粒子密度更吃帧。
- 它**只在战斗屏生效**,且**无设备分级**:再差的机器也是开局满档,要等 EMA 爬到 >26ms 才降档——开局就卡。微信端 DevTools 面板是 DOM 的、用不了,所以不做手动开关。
- 另有一处**遗留手动改动**在工作区未提交:删掉骑兵鞭扫扇区特效(`render.ts` 原 `drawWhipSweepFill` 及两处调用)。那是无条件的实验中间态,本设计把它**纳入档位**(低档省略、高档保留),而不是无条件删。
- 关联既有诊断:`perf-diagnosis-canvas-heat-jank`(A~E 已合入;F autoplace 尖峰、GC 仍在剩余未做清单,但那是另一个议题,本设计不碰 autoplace/AI/数值,故不触发 ai-balance 门禁)。

## 现状锚点(均在 `web/src/`)

- `main.ts:215-217`:`frameMsEma`、`fxQualityLevel` 状态(EMA 帧时 ms、当前档 1=满/0.4=省)。
- `main.ts:2951-2958`:战斗屏 EMA 帧时监视 + 两档迟滞升降。
- `render.ts:2739-2748`:`fxQuality`、`setFxQuality`、`getFxQuality`。
- `render.ts:2791`(火舌 `round(baseN*fxQuality)`)、`:2804`(火星 `fxQuality>0.55` 才画)、`:2850`(冰晶 `round(7*fxQuality)`)——现有 3 个档位消费点。
- `render.ts` 全文件 `createRadialGradient` 调用约 15 处(含 `drawUnlockedCellFace` 每格重建)、`shadowBlur` 数处(`:1112`/`:2076`/`:2604`/`:3137` 等)、`boardLayerCache`(`:1694`)已有棋盘离屏缓存可参考。
- `platform.ts:46` 已用 `wx.getWindowInfo`/`getSystemInfoSync` 取屏幕尺寸,但**未捕获 `benchmarkLevel`**——设备分级要在此新增强制捕获。

## 设计

### 档位模型(核心)

把 `fxQuality` 从「隐式两档」改为**显式档位常量**,用一个集中模块(新建 `web/src/quality.ts`)统一表达档位与它们各自开启的降载项。档位语义:

| 档位 | 帧预算目标 | 特效 | 基础渲染降载 |
|---|---|---|---|
| `high`(1.0) | 60fps | 全开 | 无降载(现状) |
| `mid`(0.6) | ~40fps | 粒子密度 ~60% | 径向渐变改为缓存/复用、命中爆点减量、关 blur |
| `low`(0.3) | ~30fps | 粒子密度 ~30%、省略火星/毛玻璃 | 进一步减 drawImage、全屏填充降频、爆点再减 |

`getFxQuality()` 返回档位的标量值,现有 3 个消费点继续用标量缩放,**无需改动**;新增降载项用「布尔档位开关」读取同一档位源,避免散落魔法数。

### 开机设备分级(初始档)

新增一个 `pickInitialTier()`:开机时读设备性能信号定初始档,差的机器**开局即中/低档**,不必等 EMA 爬到降档线。
- 微信端:`wx.getSystemInfoSync().benchmarkLevel`(数值越大越强,通常 0/1 差、>=20 强;不同机型基准不同,只做粗分)。捕获不到/浏览器端:回退到 `high`(浏览器多为开发/中高端,且诊断里 web backing store 反而更大是另一回事,不在此处处理)。
- 分级只定**初始档**;战斗中仍由 EMA 动态调整(见下),分级不锁死。

### 战斗中 EMA 动态调档(扩展现有监视器)

保留 `main.ts` 的战斗屏 EMA 帧时监视与迟滞思想,但**从两档扩到三档**:按 EMA 帧时在高/中/低之间升降,阈值带留迟滞防抖(升档阈值比降档阈值更严格,避免临界抖动)。EMA 只在战斗屏 + 连续循环时统计(与现有一致,菜单静置 30fps 不误伤)。
- 降档序列:high →(EMA 过高)→ mid →(持续过高)→ low。
- 恢复序列:low →(EMA 持续够低)→ mid →(更够)→ high,每级恢复阈值更严。

### 基础渲染降载(按档位开关)

这是相比现有浅机制的主要增量。各降载项都用 `quality.ts` 的布尔开关读取,**默认高档全关、中/低档逐级开启**:
- **径向渐变缓存化/复用**:`drawUnlockedCellFace` 等内容确定性(旧诊断 `cellHash01` 确定性=纯静态)的渐变,按签名缓存到离屏 canvas,复用而非每帧重建(参考已有 `boardLayerCache` 模式)。高档可仍每帧(现状),中/低档强制走缓存。
- **全屏填充降频**:背景 cover + 半透明 fillRect 这类每帧重复的全屏填充,低档隔帧或降频重绘(内容静态时)。
- **关 blur / 毛玻璃**:`drawEndlessFrost` 毛玻璃(已有 8Hz 缓存)与其它 `shadowBlur`/blur 发光,低档直接关闭或降强度。
- **命中爆点减量**:`battle.ts` 的 `bursts`/飘字/fx 对象生成数随档位减少(这是特效与基础渲染的交界,归到基础渲染降载)。

> 不做:降整体渲染分辨率(用户明确不降);不动 autoplace/AI/数值(避免 ai-balance 门禁);不暴露手动画质档。

### 遗留手动改动的归并

工作区未提交的 `render.ts`(删骑兵鞭扫扇区特效)在 worktree 里**不采用其「无条件删除」形式**,改为:扇区残影在 `mid`/`low` 档省略、`high` 档保留,接入 `fxQuality`/档位开关。最终该工作区改动会被本设计的实现覆盖,不作为独立提交。

## 取舍(已确认)

1. **标量 + 布尔双通道**:现有 3 个粒子点继续用 `fxQuality` 标量(零改动),新增降载用布尔档位开关——兼顾「少改现有代码」与「表达基础渲染的开/关降载」。
2. **开机分级 + 战斗中 EMA 双机制**:分级解决「再差也开局满档」的冷启动卡顿,EMA 解决「分级不准/中途发热掉频」的运行时波动。两者不冲突,EMA 可覆盖分级结果。
3. **迟滞恢复更严**:升档阈值严于降档,避免帧时在阈值附近抖动导致档位反复跳。
4. **不降分辨率**:用户明确;低端机靠「减绘制量」而非「降清晰度」换帧率。

## 明确不做(YAGNI)

- 手动画质档 / 画质设置 UI(纯自动)。
- 降整体渲染分辨率。
- autoplace 规划器尖峰(F)、GC 频率(剩余诊断项)——属另一议题,本设计不碰,避免触发 ai-balance 门禁。
- PvP 对手模拟、网络层优化(与渲染帧率无关)。

## 验证

- **单元测试**(`web/tests/`):`quality.ts` 的档位常量、`pickInitialTier` 分级映射(含 benchmarkLevel 缺省回退)、EMA 迟滞升降序(给定帧时序列→期望档位序列,含防抖)。vitest 在 `web/` 跑。
- **渲染计数器回归**:`web/tools/perf-count.mjs` 测改前/改后每帧 `createRadialGradient`/`save`/`fillText`/`drawImage` 计数,确认中/低档基础渲染降载生效(渐变/填充/drawImage 下降)。基准用 `perf-profile2.mjs`(已内置「教程全已见」预置,避免空棋盘),4x CPU 节流模拟低端,对比改前/改后帧 JS 耗时 p99 与掉帧。
- **视觉等价(高档)**:高档行为应与现状逐像素等价(只在不该变的地方变了才叫回归);`shot-diff.mjs` 不同端口对比高档截图。
- **typecheck 不新增**:`web/` tsc 基线不干净,验收看「不新增报错」。
- **浏览器验证**:按 `verify-web-in-browser` 记忆,改渲染/循环后真机浏览器跑冒烟(`__game` 钩子),确认战斗能进、档位切换无白屏/无报错。
